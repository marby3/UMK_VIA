# UIAPduino_VIA 高度機能実装計画

## 概要
UIAPduinoの基本動作確認が完了したため、さらなる完成度向上を目指してフェーズ別に機能追加を行います。本計画では、Webベースで完結する開発・設定環境の構築と、各種ファームウェア機能の実装を進めます。

## ユーザーレビュー事項

> [!IMPORTANT]
> - 第一段階として**フェーズ1とフェーズ2**から着手します。
> - フロントエンドの技術スタック（React/Vueなどフレームワークの導入有無、またはVanillaのまま進めるか）の確認が必要です。現状の `web` ディレクトリの構成維持で進めてよいでしょうか？

## フェーズごとの実装方針

### フェーズ1：プロジェクト基盤の構築
- **リポジトリ・ディレクトリ構成**: プラグインやGUIの実装がしやすいようにディレクトリ設計を見直します。
- **ローカルビルド環境**: ファームウェアディレクトリにMakefile等を用意し、PC上でのビルド手順（GCC等）を示すドキュメントを整備します。
- **ガイド作成**: GitHub等のOSS公開を見据えたREADMEやコントリビュートガイドを作成します。

### フェーズ2：共通UI/UXの実装
- **トップページ・レイアウト**: ヘッダー（ナビゲーション）を構築し、ルーティングにより各画面（設定・マッピング等）を切り替えられるようにします。Vanilla JSの場合は画面切り替え用のルーター関数を実装します。

### フェーズ3〜7：順次対応
- フェーズ1・2の完了後、フェーズ単位で実装計画を更新しながら順次進めます。

# フェーズ6：動作テスター機能（Key Tester）の実装計画

ユーザーの入力（打鍵）をリアルタイムで検知し、画面上で視覚的にフィードバックを返す動作テスター機能を実装します。

## 概要・目的
作成したカスタムキーボード、または既存のキーボードのすべてのキーが正常に反応しているかを確認するための機能です。シリアル通信（WebHID）を用いなくても機能するよう、ブラウザ標準の `KeyboardEvent` (keydown/keyup) を活用してOSレベルで入力されたキーを検知します。

## User Review Required

> [!IMPORTANT]
> **デフォルトレイアウトの仕様について**
> カスタムキーボードのレイアウト定義（JSON）がアップロードされていない場合、「104英語キーボード」または「109日本語キーボード」を表示する予定です。
> 今回の実装では、標準フォーマットをどこまで正確に描画するか（テンキーやファンクションキーを含めたフルサイズか、65%などのコンパクト構成か）ご希望はありますか？（まずは標準のフルサイズ・日本語/英語の切り替え機能から構築する想定です）
