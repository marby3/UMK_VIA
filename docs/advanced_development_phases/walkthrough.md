# Phase 1-4 Walkthrough (基盤構築からレイアウト・ファームウェア作成GUIの実装完了)

これまでに行った基本動作確認済みのベースに対し、本プロジェクトをより実践的・実用的でOSS公開可能な形態にするため、**プロジェクト基盤の構築**から、開発ユーザーの根幹となる**レイアウトエディタおよびファームウェアビルダーのUI構築**までを完了しました。

## 概要

> [!NOTE]
> すべての要素はWeb上のフロントエンドとして完結するようにVanilla JS・HTML・CSSを中心に構成されています。

1. **プロジェクト基盤・共通UI整備 (Phase 1 & 2)**
   - `README.md` および `CONTRIBUTING.md` の作成。
   - `index.html` および `styles.css` を大幅に刷新し、上部にルーティング可能な**トップナビゲーションバー（Glassmorphismデザイン）**を追加しました。

2. **キーレイアウト作成支援GUIの実装 (Phase 3)**
   - Canvas/Grid 上でのドラッグ＆ドロップによる直感的なキー配置機能を実装しました（`layout_editor.js`）。
   - キー幅、高さ、X/Y オフセットの直接編集機能を右サイド（または上部）のプロパティパネルに備えました。
   - 設定したレイアウトを JSON 文字列として出力（Download）し、また既存の JSON を読み込んでパース（Upload）する機能を構築しました。

3. **ファームウェア作成支援GUIとビルドの実装 (Phase 4)**
   - 基板設計からヒントを得た「直感的なピン配置」を可能にする Firmware Builder を構築しました（`firmware_builder.js`）。
   - ユーザーが指定した行（Row）・列（Col）の数に応じて、動的にセレクトボックス（CH32V003 のピンを選択）が生成されます。
   - RGB LEDの制御ピン（DIN）やロータリーエンコーダー（A相、B相など）の増減追加、マトリクス以外の拡張機能を網羅したUIです。
   - 同時押し修飾キー（Ctrl, Shift, Alt, Win）をワンタッチで複合定義できるチェックボックスを実装しました。
   - 擬似的なビルド実行とチェックプロセス（16KBのFlashチェック等の通知）をおこなうログ出力機能を設けました。

## フロントエンド実装詳細

- **画面コンテナのフルワイド対応**: PC向けの作業領域拡張として、メインコンテンツの最大幅制限（`max-width`）を1600pxまで広げ、広大なキャンバスを扱えるように設計し直しました。
- **Hardware Config & Layout Editor**: ハードウェアの基板定義（VID/PID、Row/Colなどの行列設定）とキャンバスレイアウト画面が1つの状態空間を共有するため、より高度で整合性のとれたJSON入出力が可能になりました。
  - *機能追加*: Hardware側で設定したRow/Col上限とレイアウト上の数値を監視し、不整合があればHardware画面に警告を表示するバリデーションを搭載。
- **Layout Editorの操作性の高度化**: 
  - `Ctrl + Click` による複数選択や、ドラッグ＆ドロップ範囲指定による**矩形選択（Selection Box）**を実装。
  - 新規キー追加時に、X・Y方向の配置に合わせた「Row/Col自動加算補完」機能を実装し、[0,0]から[0,1]への連番入力の手間を省きました。
  - Rotation（Angle 15度刻み対応）だけでなく、回転中心点Origin(Rx, Ry)の目印となる赤色マーカーを可視化。
- **マトリクス結線の配線チェック機能表示**: 
  - ツールバーのボタンから「同じRow」「同じCol」を持つキー同士をキャンバス上でSVGの線で結線し、配線ルートが適正か視覚的にチェックできる機能を設けました。
- **統合JSONの入出力**: ファームウェア仮想ビルド後、`KeyboardDefinition`というハイブリッドJSONフォーマットを利用した確実なレイアウトデータのロード・セーブを統合的に対応。

**[Phase 4 完了] ローカルサーバーと連携した実ビルド機能の統合**
- これまでダミーだったファームウェア出力を廃止し、**実際のCH32Vファームウェアをブラウザからビルドできる**仕組みを実現しました。
  - ルートにPythonスクリプト `build_server.py` を追加。ローカル環境で立ち上げることで `POST /api/build` エンドポイントが起動します。
  - ブラウザから Row/Colのピン指定(`PC1`, `PD2` など), マトリクスサイズ, VID/PID が送信されると、Pythonサーバーが `firmware/custom_config.h` を自動生成。
  - その直後に `make clean && make` が実行され、正常終了した際は本物の `main.bin` がブラウザ側にダウンロード送出されます。
  - これにより、ブラウザ上の直感的なGUIから直接ハードウェアピンなどのC言語実装レベルの改変を適用してコンパイルする一連のパイプラインが完成しました。

## フェーズ6：動作テスター（Key Tester）の実装完了

ブラウザの標準機能を活用した「動作テスター」機能を実装し、PCに接続されたキーボードからの入力信号を視覚的にフィードバックする画面を構築しました。

### 実装した主な機能
1. **OS非依存の打鍵テスト (KeyboardEvent)**
   - WebHID（シリアル通信）を使わず、OSが解釈したキー入力を `keydown` / `keyup` で補足するロジックを独自スクリプト (`tester_app.js`) に実装しました。これによって通常の市販キーボードもテスト可能です。
2. **デフォルトレイアウトの搭載**
   - JAVASCRIPT内に「標準109日本語」と「標準104英語」の座標データを搭載し、セレクトボックスで即座に切り替えてテストできるようにしました。
3. **カスタムレイアウト連携**
   - 開発ユーザー側で設定（JSONロード）したレイアウト（`keys` 変数）をテスターにも読み込み、自作キーボードそのままの配置で動作確認が行えるようにしました。
4. **イベントログの表示**
   - 画面下部に、どのキーコードが認識されたかをミリ秒単位の時刻付きで記録し続けるターミナル風のログ領域を追加しました。
5. **打鍵ステータスの視覚化**
   - `builder_app.css` の末尾に `.tester-key` のベーススタイルを追加しました。
   - `.active` : キーが押下されている状態（光るエフェクト、青緑色、`transform: scale(0.95)` による押し込み表現）
   - `.tested` : 過去に一度押されたことがある状態（薄い青緑色での半透明表示）
