# ユーザーからの恒久的なフィードバック・注意点ノート

このドキュメントは、ユーザーからの各種指摘事項や開発上のルールを記録し、今後の開発においてAI（私）が常にプロンプトのコンテキストとして認識・順守するためのメモ帳です。

## 🛠 開発上のルールと教訓

1. **自己レビュー（セルフレビュー）の徹底**:
   - `make`コマンドの実行をユーザーに依頼する前に、必ず自分自身で「C言語の文法エラーはないか」「ポインタや配列外参照のリスクはないか」等の静的解析を脳内で行い、完璧であると確信してから依頼すること。

2. **フロントエンド (JS/UI) の状態遷移の確実なリセット**:
   - ボタンのテキスト（例: `Flashへ保存中...`）や無効化(`disabled`)状態を変更した場合、処理が終わった後や切断状態・再接続状態になった際に、**確実に元のテキスト・状態にリセットされるロジック**を忘れないこと。

3. **ハードウェアとレイヤー処理の複雑性（スタック問題）への認識**:
   - 透過・レイヤー機能を実装するにあたり、以前の `keycode_cache`（ステートフル設計）の導入で解決したような「別のキーのON/OFFイベントによるスタック（イベント迷子）」の問題が再び発生しないよう、新機能（マクロやメディアキー等）を追加する際も**常に状態管理の不整合がないか**に細心の注意を払うこと。

4. **ブレッドボードでのテスト・検証について**:
   - Phase 6 以降、ユーザーはピンセットではなくブレッドボードで配線してテストを行っている。
   - 複数のピンが同時に操作されたりノイズが乗る可能性も上がるため、チャタリング（Debounce）処理の重要性がこれまで以上に高まることを念頭に置くこと。

以上の留意事項は、以降の開発フェーズ全てにおいて**絶対のルール**として適用し続けます。
